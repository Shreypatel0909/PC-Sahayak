# Safe Troubleshooting Principles

## Overview
Good troubleshooting is methodical and reversible. The goal is to find the cause without creating new problems or losing data. These principles apply to every category in this knowledge base and should guide the order and manner in which any fix is attempted. When advising a user, always favor the safest action that could solve the problem.

## Core principles

### 1. Reversible checks first
Always try the least invasive, easily undone actions before anything permanent. The usual order is: observe and read the error, restart, check connections and settings, run built-in troubleshooters, then repair, and only last resort to resets, reinstalls, or hardware changes. A restart or a setting toggle costs nothing and solves a surprising share of problems.

### 2. Read the error before acting
The exact error text, code, or named file is the single most useful clue. Record it precisely and use it to narrow the cause rather than guessing. Vague descriptions lead to wasted, risky steps.

### 3. Change one thing at a time
Make a single change, then test. If several changes are made at once and the problem goes away, it is impossible to know which one helped, or whether a new issue was introduced. One change, one test keeps cause and effect clear and makes everything reversible.

### 4. Back up before anything risky
Before any action that could touch data, disk repairs, formatting, resets, reinstalls, or opening a suspect drive, ensure important files are backed up to a separate location. If a drive may be failing, back up first and tread carefully, because repair tools can reduce the chance of later recovery.

### 5. Understand a command before running it
Never run a command, script, or registry edit that is not understood. Destructive commands (formatting, deleting system files, resetting network or system state) must be gated behind clear warnings and prerequisites, not offered as casual first steps. If the purpose and effect of a step are unclear, stop and find out first.

### 6. Prefer official sources
Download drivers, installers, and firmware only from the hardware or software maker, or from Windows Update. Avoid unofficial "optimizer" and "driver updater" utilities, which often cause more harm than good.

### 7. Note what you change so you can undo it
Before changing a setting, firmware option, or driver, write down the original value. Keep a short record of each step taken. This makes it possible to retrace and reverse the process if the problem is not solved or gets worse.

### 8. Know when to stop
If a step risks data or requires opening hardware beyond the user's comfort, or if symptoms point to failing hardware, stop and recommend professional help rather than pushing on. Protecting data and safety outweighs a faster fix.

## A safe default sequence
1. Observe symptoms and record the exact error.
2. Save open work and restart the device.
3. Check physical connections, power, and relevant settings.
4. Run the built-in Windows troubleshooter for the area.
5. Repair system files or the specific component (non-destructive tools).
6. Back up important data.
7. Only then consider resets, reinstalls, firmware changes, or hardware steps, each behind a clear warning.

## Warnings are not optional
Any step involving registry edits, firmware (BIOS/UEFI) changes, disk formatting, driver installs, security-software changes, or full resets must be preceded by a clear warning and a backup recommendation where data is at risk. Present these only after safer options have been exhausted.
